# decoder-confidence

Simulation and evaluation pipeline for **decoder-confidence metrics** used as
post-selection criteria in quantum error correction: given a decoded shot, a
confidence metric scores (or accepts/rejects) how much to trust the decoder's
answer, so that low-confidence shots can be discarded to trade acceptance rate
for a lower conditional logical error rate. The repository runs that pipeline
end to end for several code families, decoders, and confidence metrics, and
provides analysis/plotting code to evaluate the metrics against each other.

## Pipeline

The simulation pipeline has four conceptual stages. Only stages 2–4 are
implemented in this repository; stage 1 is external.

| Stage | Description | In this repo? |
|---|---|---|
| 1. Circuit generation | Build a Stim `.stim` circuit for a code, distance, noise model, and error rate | No — circuits are generated by an external tool and shipped pre-built under [circuits/](circuits/) |
| 2. DEM + sampling | Build the circuit's detector error model and draw random detector/observable samples | `decoder_confidence.sampling` — see [documents/STEP2_SAMPLING.md](documents/STEP2_SAMPLING.md) |
| 3. Decoding | Decode each sampled batch and compute a confidence metric per shot | `decoder_confidence.decoding` |
| 4. Analysis | Load decoding results and plot metric distributions / post-selection performance | `analysis/` (not a separate package — see [Installation](#installation)) |

## Supported codes

Read from [circuits/](circuits/) and [circuits/circuit_format.md](circuits/circuit_format.md). Circuit filenames encode
`code=,d=,rounds=,noisemodel=,p=` (plus `use_both=`/`ibm_reproduce=` for
bivariate-bicycle circuits, and `pcm=` for HGP).

| Code family | `d` present | Noise models present | `p` range present |
|---|---|---|---|
| `surface_code_Z` | 3, 5, 7, 9, 11 | `uniform`, `si1000`, `bitflip`, `phenomenological` | 0.001 – 0.1 |
| `superdense_color_code_Z` | 3, 5, 7, 9, 11 | `uniform`, `si1000` | 0.001 – 0.005 |
| `bivariate_bicycle_code_Z` | 4, 6, 12 | `uniform`, `phenomenological` | 0.001 – 0.03 |
| `hgp_code_Z` | 6 (one circuit, `pcm=example`) | `phenomenological` | 0.01 |

`circuit_format.md` also describes a `./scripts/generate_circuits` wrapper for
producing new circuits; that script does not exist in this repository
(`(unverified)` whether it exists elsewhere) — treat that part of the document
as aspirational, not a working command.

## Supported decoders

`decoder:` names are case-insensitive and hyphen/underscore-equivalent
(normalized in [decoder_factory.py](src/decoder_confidence/decoding/decoder_factory.py)).

| `decoder:` value | Backing library | Declared dependency | Notes |
|---|---|---|---|
| `ILP` | `ilp_decoder` (first-party — [AKTKN/ILP-decoder](https://github.com/AKTKN/ILP-decoder), not a third-party package) + Gurobi or CPLEX (`decoder_options.solver`) | `ilp` extra (`ilp-decoder`, `gurobipy`); CPLEX/`docplex` not declared anywhere | Exact logical-gap solve; slow. Gurobi calls are rate/seat-limited on the project's account — see [Testing](#testing) |
| `BP-LSD` / `BPLSD` | `ldpc.bplsd_decoder.BpLsdDecoder` | `bplsd` extra | |
| `MWPM` / `PYMATCHING` | `pymatching.Matching` | `mwpm` extra | Requires a DEM without 3+-detector hyperedges |
| `VIBE-LSD` / `VIBELSD` | In-repo BP-ensemble + LSD fallback, built on `ldpc.BpDecoder` | `bplsd` extra (`ldpc`) | Not a separate package — see [ARCHITECTURE.md](ARCHITECTURE.md) |
| `RELAY-BP` | `relay_bp.bp.RelayDecoderF64` | `relay` extra | Unmodified upstream [trmue/relay](https://github.com/trmue/relay) v0.2.2; not currently built/importable in this project's conda environments `(unverified elsewhere)` |

## Supported confidence metrics

Compatibility is read directly off the dispatch chain in `decoder_factory.py`
(see [ARCHITECTURE.md](ARCHITECTURE.md) for the exact branch order).

| `metric:` value | Compatible decoders | Output type | Reference |
|---|---|---|---|
| `logical_gap` | ILP only | numeric | — |
| `cluster_llr` | `BP-LSD`, `VIBE-LSD` | numeric | Lee, English & Bartlett 2026, Definition 2 (named in code comment) |
| `forced_gap_ml` | ILP, BP-LSD, MWPM, VIBE-LSD, RELAY-BP | numeric | conceptually related to the forced-gap idea below; not itself a cited reproduction |
| `linearize_logicalgap` | same 5 | numeric | — |
| `reweighted_linearized_gap` | same 5 | numeric | — |
| `ar-pec` / `ar-lec` | same 5 | boolean (accept/reject) | — |
| `wills_reproduce` | RELAY-BP (fixed by the paper's method) | numeric | Wills, Yoder & Chuang, "Forced Gap Post-Selection for Quantum LDPC Codes and their Operations", arXiv:2605.20346 |
| `forcing_degradation_test` | `BP-LSD`, `RELAY-BP` | numeric (baseline vs. forced weight/`cluster_llr` pairs) | — |

## Installation

- Python `>=3.10` (`pyproject.toml`).
- Two dependency files: [pyproject.toml](pyproject.toml) is the canonical, hand-maintained spec
  (`[project.dependencies]` plus the optional-extras groups in the tables
  above); [environment.yml](environment.yml) is a `conda env export` snapshot of a known-working
  environment, not a hand-maintained spec — some of its pinned versions
  (e.g. `ilp-decoder==0.1.1`) have no installable source in that file alone.
- `src/decoder_confidence` is an installable package (`pip install -e .`,
  optionally with extras, e.g. `pip install -e ".[bplsd,mwpm]"`). `analysis/`
  is **not** a package — it has no `analysis/__init__.py`, no `pyproject.toml`
  — its modules (`analysis.src.*`) are only importable with the **repository
  root** on `PYTHONPATH`/`sys.path`. The shell scripts under `commands/` set
  `PYTHONPATH="$ROOT_DIR/src"` directly rather than relying on an editable
  install; either approach works for `decoder_confidence` itself.

## Quickstart

```bash
export PYTHONPATH="$PWD/src"

# Stage 2: sample a small circuit (surface_code_Z, d=5, 1 round, bitflip)
python -m decoder_confidence.sampling \
  --code surface_code_Z --out_dir example_outdir \
  --noise_model bitflip --rounds 1 --d 5 --p 0.1 \
  --num_shots 1000 --det_sample_seed 0 --num_batch 1 --xyz_decoding True

# Stage 3: decode batch 1 with an ILP/CPLEX config
python -m decoder_confidence.decoding \
  --code surface_code_Z --data_dir example_outdir \
  --noise_model bitflip --rounds 1 --d 5 --p 0.1 \
  --batch_num 1 --num_workers 1 \
  --decoder_config conf/step3_config_cplex.yaml --xyz True
```

For analysis, see the scripts under `analysis/examples/` (repository root on
`PYTHONPATH`) and [USAGE.md](USAGE.md#analysis).

## Testing

```bash
python -m pytest tests/ -q -m "not e2e"
```

is the safe default (97 passed, 1 skipped as of this writing). Do **not** run
plain `pytest tests/` or `-m e2e` casually: three tests build a real Gurobi
environment to check the ILP decoder, and Gurobi API calls are both slow and
rate/seat-limited on the project's shared account. Those three are additionally
marked `@pytest.mark.gurobi` and refuse to run — erroring with an explanatory
message, not silently skipping — unless you opt in with
`RUN_GUROBI_TESTS=1 pytest -m gurobi`. See `tests/conftest.py` and
[AGENTS.md](AGENTS.md) for the full rationale.
